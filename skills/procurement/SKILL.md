# 采购申请复核

版本：1.0.0

## 何时使用

用户提出「采购 / 购买 / 申请预算 / 找供应商」这类目标，例如：

- 「采购两台办公笔记本，预算 12000 元」
- 「我们要买一套会议一体机，供应商已经报价了」

## 何时不用

- 目标是**申请系统权限**（走 `access_request`）
- 目标是**报销已有支出**（当前不支持）
- 用户只是问制度怎么规定、不涉及发起申请（走普通问答，不要建任务）

## 输入字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `purpose` | ✅ | 采购目的 |
| `items` | ✅ | 采购明细（物品或服务、数量、单价） |
| `estimated_amount` | ✅ | 预计金额 |
| `budget_code` | ✅ | 预算编号 |
| `vendor` | ✅ | 供应商 |
| `expected_date` | | 期望日期 |
| `quotation_attached` | | **只读**：由已解析的任务附件推导，模型与客户端都不可信 |
| `involves_sensitive_data` | | 是否涉及敏感数据 |

> `allowed-tools` 只列**模型能调用的**工具（这里只有只读检索）。
> 附件（报价材料）由服务端解析、抽取摘要后作为证据传入，模型没有读取附件的工具，
> 也不能自己声明"已附报价"。
>
> **写动作不是模型的工具。**`create_procurement_record` 由服务端在执行阶段调用，
> 前置条件是审计通过 + 审批通过 + 计划绑定了真实执行契约。模型不能直接触发它。

## 执行步骤

1. **抽字段**——只从用户原话里抽，缺失就保持空值，不猜金额、供应商或预算编号。
2. **申请人核对**——服务端首次抽取后统一暂停，由申请人核对字段、按需上传任务材料并手动提交；必填字段缺失时保持待补充，不要替申请人填。申请人确认不是管理员审批。
3. **检索制度**——用**制度里可能出现的正式表述**检索，而不是用户的口语说法。
   模型自己决定检索几个角度、查几次。采购至少要覆盖：
   金额分级审批权限、供应商准入、报价材料要求、涉及客户数据时的信息安全评估。
4. **生成计划**——产出结构化 `ExecutionPlan`，写明依据的制度条款。
5. **确定性规则检查**——金额门槛、报价材料、敏感数据由服务端判定，模型不能改。
6. **合规复核**——由独立的审计 Agent 复核计划，不通过就按意见逐项修订。
7. **人工审批**——中高风险、涉及敏感数据、未附报价材料时**必须**企业管理员审批。
8. **执行**——只允许调用 `create_procurement_record` 创建内部申请记录。

## 确定性规则（服务端计算，模型不得覆盖）

- 预计金额达到企业配置的审批门槛 → 提高风险等级并要求审批
- 未附经核验的报价材料 → 要求审批
- 涉及敏感数据 → 要求审批
- 三条都不触发时，**由服务端的确定性规则判定为低风险**，可直接登记、不需要人工审批

> 一句话区分：**"要不要审批"只由服务端规则决定**；模型既不能免除审批，也不能
> 声称已经免审批。模型能做的只是在 `review_notes` 里解释规则算出来的结论。

## 边界与禁止事项

- **不得**声称已完成实际采购、付款或对外下单——本 Skill 只创建**内部申请记录**。
- **不得**虚构供应商、报价或审批人。
- **不得**自行改动申请参数（金额、期限、供应商）；需要修改时只能要求申请人改后重提。
- **不得**由模型声称"免审批"或把 `requires_approval` 写成 false —— 那是服务端规则的输出，不是模型的判断。
- 企业配置的金额门槛是**风险触发线**，不是制度规定的审批上限；两者不能混为一谈。
