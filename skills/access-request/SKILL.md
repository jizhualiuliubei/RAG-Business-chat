# 系统权限申请复核

版本：1.0.0

## 何时使用

用户申请访问权限，例如：

- 「申请生产数据库订单库的只读权限，用于排查同步问题」
- 「给新同事开通 VPN 账号」

## 何时不用

- 目标是**采购**物品或服务（走 `procurement`）
- 用户是要把已有权限**授予别人**（那是员工管理，不是本 Skill）

## 输入字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `target_system` | ✅ | 承载资源的系统或平台，例如「生产数据库」 |
| `resource` | ✅ | 该系统内的具体对象，例如「订单库」 |
| `permission_level` | ✅ | `read` / `write` / `admin` |
| `data_classification` | ✅ | `public` / `internal` / `secret` / `confidential` |
| `duration_days` | ✅ | 申请天数（1–365） |
| `business_reason` | ✅ | 业务理由 |

> `target_system` 与 `resource` 必须拆开：「生产数据库订单库」要拆成
> 目标系统=生产数据库、目标资源=订单库，不能合并成一个字段。
>
> `allowed-tools` 只列**模型能调用的**工具（这里只有只读检索）。任务附件由服务端
> 解析、抽取摘要后作为证据传入，模型没有读取附件的工具。
>
> **写动作不是模型的工具。**`create_access_record` 由服务端在执行阶段调用，前置条件
> 是企业管理员审批通过。模型不能直接触发它。

## 执行步骤

1. **抽字段**——只从用户原话里抽。**用户没说期限时 `duration_days` 必须保持空值**，
   不得替他填一个「默认 30 天」。
2. **申请人核对**——服务端首次抽取后统一暂停，由申请人核对字段、按需上传权限范围等材料并手动提交；必填缺失时保持待补充。申请人确认不能替代管理员审批或实际授权。
3. **检索制度**——覆盖：账号权限申请与有效期、审批链、最小权限原则、
   数据分级（公开/内部/秘密/机密）。
4. **生成计划**——产出结构化 `ExecutionPlan`。
5. **确定性规则检查**——见下。
6. **合规复核**——独立审计 Agent 逐项复核，不通过就修订。
7. **人工审批**——本 Skill 的高风险场景**始终**要求企业管理员审批。
8. **执行**——只允许调用 `create_access_record` 创建内部权限登记。

## 确定性规则（服务端计算，模型不得覆盖）

- 申请 `admin` 权限 → 高风险
- 数据密级达到企业配置的高风险边界（默认 `secret`）→ 高风险
- 申请期限超过企业配置的边界（默认 30 天）→ 高风险
- 其余为中等风险

> 企业配置的期限与密级是**风险触发门槛**，不是资源的实际密级、也不是制度允许的最长
> 期限。不能因为「超过门槛」就要求申请人缩短，也不能要求密级等于配置值。

## 边界与禁止事项

- **不得**声称权限已经授予或系统已经开通——本 Skill 只创建**内部登记记录**。
- **不得**声称已完成多因素认证、安全评估或数据所有者认证。
- **不得**改动申请参数（期限、密级、权限级别）；需要改只能要求申请人改后重提。
- **不得**降低风险等级或取消系统要求的人工审批。
- 缺少资源专属条款时，保留「人工业务核验」边界即可，**不得**因此整体拒答，
  也**不得**宣称已获授权。
