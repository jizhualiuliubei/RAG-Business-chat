企业级 AI 知识库工作台

RAG Business Chat 将企业制度、表格、扫描 PDF、会话附件整合到一套多企业 SaaS 工作台中。系统不只回答问题，还展示证据、保留上下文、隔离企业数据，并用评测体系持续验证效果。

系统功能覆盖企业知识库完整链路

平台围绕三类用户展开：系统管理员治理平台，企业管理员管理企业资产，企业员工使用知识库问答。每个模块都服务于“可上传、可检索、可追溯、可评测、可隔离”的企业场景。

企
多企业 SaaS 与账号体系

支持 system 平台资产、企业管理员注册审核、企业员工后台创建。企业代码作为登录入口，同名用户名可在不同企业内独立存在。

  • 系统管理员：企业 CRUD、审核、禁用、代管
  • 企业管理员：员工、知识库、模型 Key、评测
  • 企业员工：本企业知识库问答和个人会话
文
文档治理与解析入库

企业管理员可新建知识库、上传制度文档、查看解析状态、失败原因、切片数量，并在删除时同步清理关系库记录和向量。

  • 支持 DOCX / PDF / OCR / CSV / XLSX / TXT
  • 表格保留 Sheet、表头、行号和值
  • 切片写入文档、章节、条款号、页码元数据
问
可信 RAG 问答工作台

员工可选择一个或多个知识库参与检索。回答区展示正文、引用证据链、来源文件、相似度和片段摘要，方便检查答案依据。

  • 问题改写、混合检索、Rerank 重排
  • 条款号精确召回与多证据补召回
  • 无依据问题触发拒答护栏
附
会话附件临时 RAG

用户提问时上传附件后，附件只属于当前企业、当前账号、当前会话。后续追问可继续使用附件内容，但不会自动进入企业正式知识库。

  • 附件解析状态、摘要、切片数可见
  • 知识库来源与附件来源分组展示
  • 附件与制度冲突时并列说明差异
评
RAG 评测中心

系统内置企业规模基准评测集，支持 retrieval 和 full 两种模式，输出逐题诊断、失败原因、报告下载和历史任务。

  • A-F 六类题型覆盖事实、细节、跨文档、场景、边界和拒答
  • AI 辅助题集默认草稿，需人工审核后运行
  • 评测任务按企业隔离
审
模型配置与审计治理

DeepSeek 对话模型和 SiliconFlow/BGE-M3 嵌入模型按企业配置。Key 加密存储、遮罩展示、连接测试，关键治理动作写入审计日志。

  • 普通企业缺 Key 不回退平台 Key
  • system 平台资产也可后台配置 Key
  • 审计覆盖审核、代管、删除、Key 更新

界面导览：从登录到问答再到治理

通过真实系统界面展示核心流程：登录进入工作台，选择知识库提问，查看引用证据，再进入后台完成文档、模型、企业和评测治理。

用户登录与企业管理员申请

登录页使用企业代码、用户名、密码和验证码进入系统。系统管理员使用 `system` 入口，企业用户使用企业代码入口。企业管理员可提交注册申请，审核通过后获得企业后台权限。

设计重点从入口就区分平台资产和企业身份，避免用户在登录后再选择组织。
安全边界企业被禁用、拒绝或软删除后，企业用户无法登录或调用业务接口。
体验账号默认可提供员工体验账号进入问答工作台，降低系统体验门槛。

问答工作台首页

首页把知识库选择、最近会话、问答输入和引用开关集中在一个操作界面。用户可以在多知识库范围内提问，也可以进入后台查看文档和评测。

检索范围左侧显示当前知识库与多选范围，未勾选的知识库不参与检索。
会话隔离最近会话按账号隔离，同一企业内管理员和员工不会互相看到会话。
附件入口输入区支持上传文件作为当前会话临时上下文。

带引用证据链的 RAG 回答

回答不仅给出结论，还将可用证据组织成引用链。用户可检查命中的知识库、文件名、章节路径、片段内容和相似度，判断答案是否可靠。

回答策略正文中引用编号对应下方来源，证据不足时提示知识库无依据。
来源区分正式知识库来源和会话附件来源分别标识，不把临时附件当作企业制度。
可追溯每个 chunk 携带 enterprise_id、kb_id、doc_id、source 和 chunk_id。

知识库治理与文档管线

后台以知识库为单位管理文档生命周期。管理员可查看每个文件的解析状态、切片数量、失败原因，支持单文件删除和批量删除。

解析状态processing / done / failed 状态直接暴露，失败时显示可排查原因。
入库流程解析文本、结构化切片、生成 embedding、写入 Zilliz 元数据。
清理策略删除文档时按 enterprise_id + kb_id/doc_id 清理向量，降低残留命中风险。

系统管理员企业治理

企业管理支持新建、查看、编辑、审核通过、拒绝、启用、禁用和软删除。企业代码唯一，system 平台资产不可删除，所有治理动作进入审计。

表单校验企业名称和企业代码必填；企业代码、手机号、邮箱、Logo URL 等前后端校验。
审核流程企业管理员注册后生成待审核企业和账号，系统管理员审核后才可登录。
代管视角系统管理员可切换企业视角协助治理，代管操作写入审计日志。

DeepSeek 与 SiliconFlow Key 路由

每个企业单独保存对话模型和嵌入模型配置。保存与连接测试分开，连接测试使用当前输入优先，不自动写入数据库。

Key 安全加密存储，页面只显示已配置状态和后四位，审计日志不记录完整 Key。
调用路由问答和 full/e2e 评测走 DeepSeek；文档向量化、query embedding 和检索走 SiliconFlow。
失败策略普通企业 Key 缺失或不可用时直接提示配置，不回退 system 平台 Key。

评测任务、逐题诊断和报告下载

评测中心用于验证检索命中、章节命中、答案覆盖、引用正确、拒答正确和耗时。任务中断后可提示重新评测，历史任务和报告按企业隔离。

题集来源builtin、uploaded、ai_generated、human_reviewed 分开标识。
运行模式retrieval 只验证检索链路，full 同时验证模型回答和评分。
诊断输出失败样例会给出题号、问题、失败原因和修复建议。

平台治理审计

审计中心记录企业审核、企业状态变更、模型 Key 更新、文档删除、评测删除、代管企业等关键操作，方便平台治理和问题追踪。

中文动作前端展示中文操作名称，避免内部接口名影响阅读。
查看范围系统管理员查看平台治理记录，企业管理员只查看本企业记录。
敏感保护日志不保存模型 Key 明文和用户密码。

一条业务路径贯穿整个系统

展示系统时可以按这条路径讲解：从企业入口登录，到上传资料，再到问答验证、评测诊断和平台治理。

1. 用户登录

企业代码 + 用户名 + 密码进入企业工作台。

2. 配置模型

企业管理员保存并测试 DeepSeek / SiliconFlow Key。

3. 上传文档

制度、表格、PDF 解析为结构化切片并写入向量库。

4. 提问溯源

员工获得带证据链、来源文件和引用编号的回答。

5. 评测复盘

运行基准题集或审核后的题集，输出诊断报告。

RAG 设计：围绕企业制度问答做准确率工程

企业制度问答不是普通闲聊，问题里经常包含条款号、文件名、金额阈值、时间限制、审批角色和跨文档条件。系统把准确率工程拆成“结构化入库、查询理解、多路召回、重排补证、受控生成、评测闭环”六层，让答案尽量来自可追溯证据，而不是依赖模型猜测。

文档解析

系统支持 DOCX、PDF、扫描 PDF OCR、TXT、CSV、XLSX/XLS。表格不会被压成一团文本，而是转换为包含 Sheet、表头、行号、字段和值的可检索文本。

Sheet: 绩效系数 · 第 5 行 员工级别: P3；绩效等级: A；绩效系数: 1.2
析
解析层保留制度结构

Word 按段落、标题和条款组织；PDF 优先读取文本层，扫描件走 OCR 兜底；Excel/CSV 会把 Sheet、表头、行号和字段值展开成自然语言，避免表格关系在向量化前丢失。

片
切片层保留上下文

默认 350 字符切片、80 字符重叠，适合企业制度中“一条规则 + 条件 + 例外”的长度。每个 chunk 写入文档名、章节、条款号、页码/Sheet、enterprise_id、kb_id、doc_id 和 chunk_id。

检
检索层兼顾语义与硬命中

向量检索处理语义相近问题，BM25 处理制度编号和关键词，条款号精确召回处理 HR-01-001 这类短编号，元数据过滤保证只在当前企业和选中的知识库内检索。

排
重排层提高证据质量

候选结果先融合去重，再通过 Rerank 把最相关证据前置。跨文档问题会补召回主证据和辅助证据，避免只命中其中一个制度导致答案要点缺失。

答
生成层限制幻觉

Prompt 要求按引用编号作答，证据不足时明确说明知识库无依据；正式知识库和会话附件分开注入，附件与制度冲突时并列说明差异，不直接合并成确定结论。

测
评测层持续校准

评测中心同时看 Top-K 文档命中、章节命中、答案要点覆盖、必需证据命中、引用正确和拒答正确，定位问题属于召回、重排、生成还是拒答策略。

数据库与权限：企业和账号隔离是底座

所有业务实体围绕 `enterprise_id` 归属，个人会话围绕 `user_id` 再隔离。Zilliz 使用统一 collection，但检索和删除必须同时带企业、知识库、文档元数据过滤，避免跨企业命中和残留向量污染。

数据域核心表隔离与约束
企业与用户enterprise、users、enterprise_model_key企业状态流转；用户名企业内唯一；模型 Key 加密保存并遮罩展示。
知识库与文档knowledge_base、document知识库企业内唯一；文档记录 enterprise_id、kb_id、解析状态、切片数。
会话与附件conversation、message、conversation_attachment、conversation_attachment_chunk按 enterprise_id + user_id + conversation_id 隔离，附件只在当前会话内参与 RAG。
评测与审计evaluation_dataset、evaluation_run、evaluation_case_result、audit_logs题集、任务、报告和审计按企业过滤；system 管理平台资产。
