# 评测体系

## 评测目标

评测中心用于持续验证 RAG 系统是否真正命中正确证据、覆盖答案要点、正确引用来源，并在知识库没有依据时拒答。

## 题集来源

| 来源 | 说明 |
| --- | --- |
| `builtin` | 内置基准题集，如企业规模 360 题 |
| `uploaded` | 管理员上传的人工题集 |
| `ai_generated` | AI 辅助生成的草稿题集，默认需要人工审核 |
| `human_reviewed` | 已经过人工审核和证据锁定的题集 |

AI 辅助题集不会直接替代内置基准。生成后需要人工检查证据原文、标准答案、答案要点和引用要求。

## 题集版本

当前实际存在三套题集，题数和分类口径并不统一，比较指标时需先确认口径：

| 题集版本 | 题数 | 分类 | 说明 |
| --- | ---: | --- | --- |
| `enterprise_scale_v1` | 36 | A–E | 手写基准题集。 |
| `enterprise_scale_360_v1` | 360 | A–F | 全量基准题集，含 F 类负例。 |
| `eval_rag.py` 的 CASES | 52 | A–E | `/api/evaluations/catalog` 返回的题集，工作台概览页（`Dashboard.vue`）调用的就是这一套。 |

评测中心（`AdminView.vue`）使用前两套。360 题集分类分布为 A=96、B=60、C=60、D=72、E=48、F=24；其中 `negative_case`=24（F 类），带 `required_citations`=336。

## 六类题型（360 题集口径 A–F）

| 类别 | 名称 | 验证重点 |
| --- | --- | --- |
| A | 单文档事实检索 | 能否找到单一制度事实 |
| B | 单文档细节定位与条款解释 | 能否命中条款并解释硬信息 |
| C | 跨文档关联推理 | 能否同时召回主证据和辅助证据 |
| D | 场景应用与规则计算 | 能否把制度应用到具体场景 |
| E | 边界条件与易错判断 | 能否识别误读和例外 |
| F | 文档未覆盖与幻觉测试 | 能否在无依据时拒答 |

A–F 是 360 题集（`enterprise_scale_360_v1`）的口径；`enterprise_scale_v1`（36 题）和 `eval_rag.py`（52 题）只有 A–E 五类，没有 F 类拒答题。

## 评测模式

| 模式 | 调用模型 | 说明 |
| --- | --- | --- |
| retrieval | 否 | 只验证检索命中、章节命中和证据命中 |
| full | 是 | 完整执行检索、生成、答案评分和报告汇总 |

## 指标口径

- Top-K 文档命中率：期望文档是否进入前 K 个检索来源。
- 章节级命中率：期望章节或条款是否进入上下文。
- 答案要点覆盖率：模型回答是否覆盖标准答案中的硬要点。
- 必需证据命中率：题目要求的 citation 是否全部命中。
- 主证据/辅助证据命中率：跨文档题是否同时拿到核心证据与补充证据。
- 引用正确率：回答中引用是否来自实际检索来源。
- 拒答正确率：F 类未覆盖问题是否明确说明知识库无依据。

## 后续优化方向

- 继续优化跨文档 C 类题的答案要点覆盖。
- 加强 F 类拒答判定，减少相似但无依据内容导致的误答。
- 引入独立评测模型或规则评测器，降低“出题模型与答题模型相同”的自测污染。
- 将评测报告产品化为趋势对比和失败聚类面板。
