# 部署说明

## 线上体验

线上地址：[http://118.31.45.253/](http://118.31.45.253/)

## 本地运行

复制环境变量模板：

```powershell
copy .env.example .env
```

后端：

```powershell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

前端：

```powershell
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

浏览器访问：`http://127.0.0.1:5173`

## 生产部署

推荐部署结构：

- Nginx 托管前端静态文件并反向代理 `/api`。
- systemd 托管 FastAPI 后端。
- MySQL 作为关系数据库。
- Zilliz Cloud 作为向量数据库。
- 企业模型 Key 通过后台配置。

生产环境模板：

- `deploy/env.production.example`
- `deploy/nginx/kb-workbench.conf`
- `deploy/systemd/kb-workbench-backend.service`

## 环境变量重点

| 变量 | 说明 |
| --- | --- |
| `DB_DRIVER` | `sqlite` 或 `mysql`。 |
| `AUTH_SECRET_KEY` | JWT 签名密钥，生产环境必须替换。 |
| `DEEPSEEK_API_KEY` | 本地开发或 system 兜底 Key。 |
| `SILICONFLOW_API_KEY` | 本地开发或 system 兜底 Key。 |
| `MILVUS_URI` / `MILVUS_TOKEN` | Zilliz/Milvus 连接信息。 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 超长章节兜底切分参数（主策略为整章成块，不使用这两个值）。 |
| `ENABLE_RERANK` | 是否启用重排。 |
| `HISTORY_ROUNDS` | 已废弃，未接入任何代码，保留仅为兼容旧配置。 |
| `ENABLE_MIDDLEWARE` | 是否启用摘要和隐私中间件。 |

说明：主问答链路的记忆压缩由 `HISTORY_SUMMARY_TRIGGER_MESSAGES`（默认 6）和 `HISTORY_SUMMARY_KEEP_MESSAGES`（默认 2）控制：历史超过 6 条时把更早内容压成摘要，保留最近 2 条原文。

## LangSmith tracing

批量评测时建议关闭 tracing，避免触发 LangSmith 月度额度限制：

```env
LANGCHAIN_TRACING_V2=false
LANGSMITH_TRACING=false
```

## Zilliz 注意事项

向量 collection 需要能保存或兼容以下元数据：`enterprise_id`、`kb_id`、`doc_id`、`source`、`chunk_id`、`text`（章节与条款号拼进 `text` 结构头，不是独立字段）。

代码对旧 schema 做字段探测兼容：旧 collection 缺少 `enterprise_id` 时，写入该字段会被跳过，**企业过滤也会被静默跳过**——不会阻断上传，也不会报字段不匹配。真正的风险是「企业过滤静默失效，存在跨企业命中风险」。因此如果使用的是旧的 collection，建议重建演示知识库向量数据，补齐 `enterprise_id` 字段，确保企业隔离真正生效。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 8001 端口占用 | 结束旧后端进程或换端口启动。 |
| 前端无法访问 | 确认 Vite dev server 是否启动，端口是否为 5173。 |
| 上传文档失败 | 检查企业 SiliconFlow Key、Zilliz 配置、文件格式、OCR 依赖。 |
| 问答模型失败 | 检查企业 DeepSeek Key、Base URL、模型名和额度。 |
| 评测中断 | 后端重启会中断内存任务，前端应提示重新评测。 |
