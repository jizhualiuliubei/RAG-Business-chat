# 技术架构

## 架构总览

![系统整体架构](images/system-architecture.svg)

RAG Business Chat 采用前后端分离、服务分层、多租户上下文贯穿的架构。前端负责产品交互，后端负责业务编排和模型调用，关系库保存业务数据，Zilliz/Milvus 保存向量数据，DeepSeek 和 SiliconFlow 分别承担生成和 embedding。

## 前端架构

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 应用壳 | `frontend/src/App.vue` | 登录态、页面切换、顶部状态、全局布局。 |
| 登录页 | `LoginView.vue` | 企业代码登录、企业管理员注册、验证码交互。 |
| 首页工作台 | `Dashboard.vue`、`ChatArea.vue`、`Sidebar.vue` | 知识库选择、会话列表、问答输入、引用证据、附件交互。 |
| 知识库治理 | `DocManager.vue` | 知识库创建、文档上传、解析状态、批量删除。 |
| 后台管理 | `AdminView.vue` | 企业管理、用户管理、模型配置、RAG 评测、审计日志。 |
| API 封装 | `frontend/src/api/api.js` | 统一请求封装、Token 传递、接口调用。 |

前端设计原则：普通员工只看到工作台；企业管理员看到本企业后台；系统管理员看到平台治理能力。模型 Key 输入框只在保存或测试时发送，不把已保存 Key 明文展示给用户。

## 后端架构

| 层级 | 文件 | 职责 |

## 登录鉴权链路

1. 用户提交企业代码、用户名、密码。
2. 后端按 `enterprise.code + username` 查询账号。
3. 校验企业状态：未审核、禁用、软删除企业不可用。
4. 校验密码摘要和用户状态。
5. 返回 JWT，Token 中包含用户 ID、角色和企业 ID。
6. 后续接口从 Token 解析当前企业上下文。

## 文档上传解析入库链路

1. 企业管理员选择知识库并上传文件。
2. 后端创建 `document` 记录，状态为 `processing`。
3. 后台任务读取企业 SiliconFlow Key。
4. Loader 解析 DOCX/PDF/OCR/TXT/CSV/XLSX。
5. Splitter 识别章节、条款号、页码或 Sheet，并生成结构化 chunk。
6. Embedding 模型生成向量。
7. Zilliz 写入向量和元数据：`enterprise_id`、`kb_id`、`doc_id`、`source`、`section`、`clause_id`、`chunk_id`。
8. 文档状态更新为 `done` 或 `failed`。

## 普通 RAG 问答链路

1. 前端发送问题、知识库 ID、会话 ID。
2. 后端校验会话是否属于当前 `enterprise_id + user_id`。
3. 读取最近历史、用户档案和会话附件摘要。
4. 对问题做条款号识别和查询改写。
5. 执行向量检索、BM25、条款精确召回和元数据过滤。
6. 对候选进行融合排序、去重、Rerank、多证据补召回。
7. 拼接知识库来源和附件来源上下文。
8. 使用当前企业 DeepSeek Key 生成回答。
9. 保存用户消息、AI 消息、引用来源、模型名和 Token 用量。

## 会话附件 RAG 链路

1. 用户在当前会话上传附件。
2. 附件记录写入 `conversation_attachment`，带 `enterprise_id + user_id + conversation_id`。
3. 解析文本、生成摘要和切片。
4. 切片写入 `conversation_attachment_chunk`。
5. 后续提问时只检索当前账号当前会话的附件切片。
6. 回答引用区区分知识库来源和会话附件来源。

附件不自动进入企业知识库，不会被同企业其他账号看到。

## 企业模型 Key 路由链路

| 场景 | 使用 Key |
| --- | --- |
| 普通企业问答 | 当前企业 DeepSeek Key。 |
| 普通企业上传/检索/评测检索 | 当前企业 SiliconFlow Key。 |
| 系统平台资产 | `system` 企业保存的模型 Key，开发环境可使用 `.env` 兜底。 |
| 企业 Key 缺失 | 请求失败并提示管理员配置，不回退平台 Key。 |

## 评测任务链路

1. 管理员选择题集、知识库和模式。
2. 后端创建 `evaluation_run`。
3. retrieval 模式只执行检索和证据指标计算。
4. full 模式执行检索、模型回答、答案覆盖评分、拒答评分和引用评分。
5. 逐题写入 `evaluation_case_result`。
6. 汇总指标写入 `summary_json`。
7. 前端展示进度、任务历史、失败原因和报告下载。

## 部署架构

生产环境推荐：

- Nginx：静态前端资源和 `/api` 反向代理。
- systemd：托管 FastAPI 后端服务。
- MySQL：保存业务数据。
- Zilliz Cloud：保存向量数据。
- DeepSeek/SiliconFlow：按企业 Key 调用。
